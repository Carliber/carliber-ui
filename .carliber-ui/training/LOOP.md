# 技能自进化循环账本

> 机制:针对弱点编需求 → 实战 → 问题归因 → 改进规则 → 更新弱点池 → 下一轮。产物在本目录,规则改进进仓库(CHANGELOG 记录)。不对对外发布负责,只对设计能力负责。

## 弱点池(按优先级)

| # | 弱点 | 依据 | 状态 |
|---|---|---|---|
| W1 | 表单交互态从未实战 | 全部历史产物无表单 | **R1 完成** → 基线补表单控件规格+浅底色谱;challenge 第 7/8 维补规则 |
| W2 | 数据可视化浅水区:只有单系列直方图;多系列/图例/轴/tooltip 联动没做过 | cockpit 单图 | **R2 候选** |
| W3 | 多页一致性没校准:所有产物单页,导航/风格跨页一致性零验证 | 产物清单 | 排队 |
| W4 | 说服型深路径:滚动叙事/情绪节奏只走过 homepage 浅水区 | homepage 无滚动叙事 | 排队 |
| W5 | 评审毒舌度:自己评自己易放过;对抗性评审机制弱 | 两轮评审均一次通过 | 长期 |
| W6 | 移动优先设计只验过折叠,未做过移动原生布局 | 产物全桌面 | 排队 |
| W7 | 品牌辨识度:产物干净但安全,无"一眼认得出"的强概念 | showcase 自评 | 排队 |
| W8 | 工具:交互态截图需逐态写 steps,时序态(提交中)抓取窗口脆 | R1 实操 | 已缓解(shoot --steps 可用),观察 |

## 循环日志

### R1 · 表单交互态(针对 W1)✅

- 需求:MC 白名单申请表单,六态(默认/聚焦/校验错误/提交中/成功/禁用)全部真实交互触发,逐态截图
- 状态:完成(六态证据 s1–s7)

**发现(看图评审,代码层查不出)**:
1. 警示黄字放灰槽底 1.05:1 → 语义色改边框承载(修)
2. emoji 当图标,像素语境硬伤 → 删(修)
3. checkbox 浏览器原生白块+蓝勾,材质违和 → 自绘像素勾选框(修)
4. 链接浏览器默认蓝/基线亮蓝 #1190FF 在灰面板上仅 1.90:1 → 浅底深档 #0a5bb5(修)
5. 错误文案 #a94438 灰底 3.4:1 偏低 → 加深 #8f2f24(修)
6. 方向卡曾用无依据视口值 1440×900 → 触发 v1.0.3 视口去固定值(已修)

**规则改进(v1.0.5)**:
- minecraft 基线新增「表单控件规格 + 浅底文本色谱」节(输入框三边态/自绘勾选/单选复用 widgets/灰底文本色 4 档,全部实测值)
- challenge 第 4 维:必须过补「语义色在实际底色上验证」,反模式补「警示色文字放中灰底」
- challenge 第 5 维:反模式补「emoji 当图标」
- challenge 第 7 维:必须过补「平台默认样式纳管」,反模式补「链接默认蓝/原生控件直用」
- challenge 第 8 维:必须过补「表单类六态齐全且由真实交互触发」
- visual-review:主 Agent 能看图时按手册标准看图评审(替代自检降级)
