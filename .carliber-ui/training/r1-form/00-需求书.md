# R1 需求书 · MC 服务器白名单申请表单

> 弱点:W1 表单交互态。验收焦点是**状态机的完整与可辨**,不是页面美观。

## 页面

白名单申请表单页(MC 材质语境,衔接 cockpit 世界观),1280×800。

## 必须覆盖的六态(全部在一张页面以真实形态呈现)

1. **默认态**:标签+输入框占位
2. **聚焦态**:边框变白(基线 GuiTextField 规格),光标可见
3. **校验错误态**:非法输入(如 MC ID 含非法字符)——错误边框 #ffa8a8 + 原版红字错误文案,错误紧贴字段
4. **提交中态**:按钮禁用灰+文字"提交中…",不可重复点击
5. **成功态**:整表单替换为原版风格确认面板(绿色 checkmark 语言)+"加入白名单"按钮
6. **禁用态**:提交按钮在必填项为空时禁用(A0A0A0 文字)

## 字段与校验规则

- MC ID(必填):`[a-zA-Z0-9_]{3,16}`,非法即时报错
- 服务器来由(必选,miniui 式无,用原版按钮组单选):朋友邀请/论坛/其他
- 留言(选填,多行,≤140 字,实时字数)
- 阅读规则勾选(必勾才能提交)

## 约束

- 基线同 cockpit(1 GUI px = 3 CSS px,禁则全套)
- 错误文案用产品语气,不用"输入错误"这种机器话
- 键盘可达:Tab 顺序=视觉顺序;错误时焦点落首个错误字段

## 验收

- 六态全部有独立截图证据
- 状态切换全部由交互触发(不是摆六张静态图)
- 键盘走一遍 Tab 流
