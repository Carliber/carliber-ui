# 自进化:训练循环方法论

返回 [主入口](../SKILL.md)。本技能的规则不是一次写成的,而是「弱点池 → 针对性需求 → 实战 → 归因 → 改规则」循环打磨出来的。这篇记录循环本身的机制与纪律,供复制这套方法时参考;日常循环记录在本地账本(不入库)。

## 循环结构

1. **弱点池**:一张优先级表,每项写「弱点名 + 状态」。入池来源:实战翻车、盲测漏抓、外部纠正。出池标准:规则补上且回归验证通过。没有新弱点的轮次做回归验证或产物体检,不硬造需求。
2. **针对性需求**:围绕弱点编一个小而真实的任务(一页、一个状态、一个极端场景),能让弱点暴露即可。需求书上写清场景与验收,不写空话。
3. **实战**:按技能主流程完整走,产物留档。
4. **归因**:抓到的问题逐个问「为什么规则没拦住」——是规则缺失、规则有但没钩进检查点,还是钩了但表述不可执行。三类修法不同:缺的补规则、没钩的挂钩子、不可执行的改写成可判定。
5. **改规则**:规则进 references 与矩阵,版本号 bump,CHANGELOG 记一行;产物归本地工作目录。

## 纪律(痛感换来的)

- **断言前读原文语境**:grep 计数、lint 提示都可能误报,归因前看原文。
- **引用数值注明出处**:视口、比例、阈值,写不下出处就不写数。
- **文件修改只用编辑工具**:脚本批量替换是惯性违规高发区,同串多变体也拆多次编辑。
- **状态切换清旧内容**:改状态必须清上一状态残留,孤立空态是真 bug。
- **改动后回归**:新规则生效后,旧产物欠新账要回审;token 类改动(色/字号/间距)归档后逐页截图复验。
- **同一问题两次复发 → 机制消除**:不靠人肉同步清单,改结构或写脚本让问题不再可能发生(常青文案、单一权威源、一键发布脚本)。

## 多轮收敛的用法

单任务打磨的轮次纪律见 [多轮对比收敛](iterate.md);训练循环与之的区别:循环的每轮是独立小任务,不追求单任务评分收敛,而追求弱点池清空。两者共用同一套截图取证与矩阵检查。

## 何时停止

- 弱点池清空且回归全绿 → 进入「真实使用反馈驱动」阶段,不再自造需求。
- 连续多轮零新发现 → 换审查维度(链接/性能/token/一致性)或接受稳态,硬编需求只会产生噪音。
